# Requirements

Source: the phase 2 requirements of task 1 of the DLBDSEDE02 portfolio, and
the commitments of the revised concept. A requirement is only ticked when it
is implemented and checked by a test, a script or a reproducible command.
The full paraphrase of the examination is in `docs/course-context.local.md`,
which is not committed.

## Requirements of the task

| Id | Requirement | Status | Where |
| --- | --- | --- | --- |
| R1 | The database runs in Docker from an open source image on Docker Hub | done | `docker-compose.yml` (official `mongo:8.0.38`, ADR-0009), `db/init-replica-set.js`, `tests/integration/test_stack.py` |
| R2 | A script sets up the database inside the container | done | `db/setup-database.js`, service `mongo-setup` in `docker-compose.yml`, `tests/integration/test_database.py` (ADR-0010) |
| R3 | A Python script connects to the database and loads the sample data | done | `src/citysense/loader.py`, `store.py`, `config.py`, `__main__.py` (ADR-0012), `tests/unit/test_loader.py`, `tests/integration/test_loading.py` |
| R4 | A Dockerfile automates the entire process | done | `Dockerfile` (two stages, pinned bases, non-root user, `uv sync --locked`), service `loader` in `docker-compose.yml` (ADR-0012) |
| R5 | The code is in an open GitHub repository | open | The repository is local and has no remote; creating the public repository and publishing the history is a step for the student |
| R6 | Cloning the repository and running the containers loads the sample data automatically | done | `docker compose down -v && docker compose up --build` loads 405,171 readings and the loader container exits with code 0, checked by `test_the_stack_stored_the_sample_without_its_duplicates` and `test_the_loader_container_of_the_stack_exited_with_code_0` in `tests/integration/test_loading.py`; the image was also built from a copy of the tracked files alone, which holds none of the tooling files |
| R7 | The repository contains a system description with the expected usages and the place of the system in a larger end user system | done | `README.md`: purpose, the three users and what each reads, a diagram of the place between sensors, front ends and operations, quick start, verification, configuration, structure, data source and limits; `tests/unit/test_readme.py` checks the paths and the figures; the quick start was followed on a copy of the tracked files alone, which loaded 405,171 readings and ended with exit code 0 |

## Commitments of the concept

| Id | Commitment | Status | Where |
| --- | --- | --- | --- |
| C1 | The sample data is loaded in daily batches | done | nine daily batches, pinned per day in `tests/unit/test_sample_data.py` (`batches.py`, ADR-0011) and in `tests/integration/test_loading.py` (`loader.py`, ADR-0012) |
| C2 | A failed batch can be rerun without creating duplicates | done | `test_an_interrupted_batch_is_repeated_and_ends_with_the_flags_of_an_uninterrupted_load`, `test_a_second_load_without_the_batch_log_inserts_nothing` and `test_a_later_batch_is_not_loaded_after_a_failure`; the demonstration with a loader that is killed with SIGKILL in the middle of a batch, whose result equals an uninterrupted load document for document, is `scripts/demo_crash_rerun.sh` with its output in `docs/evidence/crash_rerun.txt` (ADR-0015) |
| C3 | The 13 duplicate rows of the source are absorbed | done | the identifier (`identity.py`) gives the 13 duplicates the same identifier, pinned in `tests/unit/test_sample_data.py`; the loader reads 405,184 rows, inserts 405,171 and finds 13 already present, pinned per day in `tests/integration/test_loading.py` |
| C4 | Implausible readings are flagged, kept, and excluded from summaries and alerts | done | The rules flag 580 readings, including all 7 zeros and 38 low humidity readings (`validation.py`, ADR-0011, `tests/unit/test_sample_data.py`); the flags are stored with every reading, 580 of them (`test_the_flagged_readings_are_stored_and_counted`); the summaries exclude them, as their counts add up to the 404,591 valid readings and the statistics cover valid readings only (`tests/integration/test_derived.py`); the alerts are judged on those summaries, and `test_a_flagged_reading_with_an_extreme_value_does_not_raise_an_alert` in `tests/integration/test_alerts.py` shows that a flagged value of 99 degrees raises none (ADR-0014) |
| C5 | A batch log records every run, and lost connections are retried | done | The batch log with status, attempts and counts is checked (`tests/integration/test_loading.py`), and `docs/evidence/crash_rerun.txt` shows an interrupted batch with 2 attempts; the loss of the primary during a load is survived, see `docs/evidence/failover.txt`, where the driver repeated the write in flight after waiting for the election and the loader logged no retry of its own; the retry schedule of the loader is covered by unit tests with injected errors (`tests/unit/test_loader.py`) and was not triggered on the stack (ADR-0015) |
| C6 | Hourly and daily summaries carry reading counts and coverage | done | `src/citysense/aggregation.py` (ADR-0013); `tests/integration/test_loading.py` (counts add up to the 404,591 valid readings, per hour and per day; coverage range per device; partial last hour), `tests/integration/test_derived.py`, `tests/unit/test_aggregation.py`, `tests/unit/test_sample_data.py` (the rejected definition of coverage) |
| C7 | The latest valid value per sensor carries its measurement time | done | collection `latest`, one document per device with `ts` and `reading_id` (ADR-0013); `test_latest_is_the_newest_valid_reading_of_each_device`, and the guard against moving backwards in `test_rerunning_an_early_day_changes_neither_the_summaries_nor_latest` and `test_loading_an_earlier_day_again_never_moves_the_latest_value_backwards` |
| C8 | Alerts follow the alert model: deduplicated, with hysteresis, capped, with sensor silent and batch failed alerts | done | `src/citysense/alert_rules.py` (pure rules), `alerting.py` (evaluation), `config/alert_thresholds.toml` (ADR-0014); `tests/unit/test_alert_rules.py` covers deduplication, the clear hour, the cap with `alerts_suppressed`, the horizon and a silent alert for an hour without a summary; `tests/integration/test_loading.py` pins the 14 threshold alerts of the sample week per metric and device, none silent, none suppressed, and that a rerun of every day leaves the alerts unchanged; `tests/integration/test_alerts.py` covers the sensor silent, acknowledged, capped and batch failed cases on made up data; the acknowledgement by an engineer is shown in B8 |
| C9 | A compound index on device and descending timestamp | done | index `device_ts` in `db/setup-database.js`, checked by `test_readings_index_serves_ranges_per_device` |
| C10 | A TTL index on raw readings, summaries kept | done | index `ingested_at_ttl`; `test_the_ttl_monitor_removes_an_expired_reading_and_keeps_a_current_one` and `test_only_raw_readings_expire` |
| C11 | A three node replica set survives the loss of the primary during a load | done | `scripts/demo_failover.sh` kills mongo1, the primary, with SIGKILL in the middle of a batch; a new primary is elected after about 11 seconds, the loader ends with exit code 0, and every collection equals an uninterrupted load, output in `docs/evidence/failover.txt` (ADR-0015) |
| C12 | New metrics from future sensors are accepted without a schema change | done | validators allow additional fields, `test_a_reading_with_an_unknown_extra_metric_is_accepted` |
| C13 | The figures about the sample data quoted in the concept are reproduced by a script and pinned by a test | done | `scripts/profile_data.py`, `tests/unit/test_sample_data.py`, `data/README.md` |
